# Sources

티켓 조사 때 보는 순서와 각 출처에서 꺼낼 것입니다. 도구 이름은 예시이고, 쓰는 도구에 맞게 바꿉니다.

| 순서 | 출처 | 꺼낼 것 | 자주 놓치는 것 |
|---|---|---|---|
| 1 | 이슈 (Linear 등) | 제목, 본문, 요청자, 링크, 브랜치 이름, 댓글 | 본문의 "관련 링크"가 실제 PRD다 |
| 2 | 채팅 스레드 (Slack 등) | 요청 원문, 누가 무엇을 맡기로 했는지, 이후에 바뀐 범위 | 스레드 아래쪽의 범위 변경, 요청자가 나눈 문의 유형 |
| 3 | PRD (Notion 등) | 배경, 문제 정의, 목표, 기능 명세, 디자인 칸 | 탭 안 내용, 버튼·하위 블록처럼 fetch에 안 나오는 블록 |
| 4 | 고객 요청 / 티켓 | 제보자, 제보일, 우선순위 점수, 실제 표현 | PRD 속성에 연결된 티켓 id |
| 5 | 이전 작업 로그 | 같은 티켓·주제로 멈춘 지점과 이유 | 티켓 번호 없이 주제어로만 남은 기록 |
| 6 | 코드 | 상태별 실제 동작, 이미 있는 안내 문구 | 다른 진입 경로(다이얼로그)에 이미 있는 안내 |
| 7 | 운영 화면 | As-is 캡처 | 데이터가 있어야만 보이는 상태 |

## 기록 형식

```
- 요청: {요청자}, {경로}, {날짜}. 원문: "{인용}"
- PRD: {배경 한 줄} / 문제 정의: {있음·비어 있음} / 목표: {있음·비어 있음}
- 고객 요청: {제보일}, {유형}, {점수}
- 동작(코드): {상태} → {결과} ({file:line})
- 결정 필요: {PRD가 정하지 않은 것}
```
