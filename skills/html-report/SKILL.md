# HTML Report

한 가지만 합니다. 이미 모은 내용을 읽기 좋은 HTML 보고서로 만듭니다. 무엇을 조사할지(`ticket-brief`), 무엇을 구현했는지(`impl-report`)는 정하지 않습니다.

## 1. 먼저 읽을 곳 (필수)

작업할 때마다 원본을 새로 받아 읽습니다. 사본을 이 파일에 옮겨 두지 않습니다.

```bash
curl -s https://salesmap.kr/design.md            # 판단 규칙, Self-check
curl -s https://salesmap.kr/design/patterns.md   # "## Report" 절
curl -s https://salesmap.kr/design/token.md      # 토큰 블록과 전역 설정
curl -s https://salesmap.kr/design/components.md # 필요한 컴포넌트만
```

- 토큰 블록과 전역 설정은 `token.md`에서 그대로 붙여 넣습니다. hex를 새로 만들지 않습니다.
- 섹션 간격, 제목 크기 같은 시각 규칙은 design.md를 따릅니다. 이 파일에 다시 적지 않습니다.
- 내보내기 전에 design.md의 **Self-check**를 통과시킵니다.

## 2. 골격

```
header   제목(명사형) · 티켓 번호 · 기준일 · (구현이면) 브랜치와 커밋 상태
summary  결론 3줄 이내. 굵게는 줄마다 한 곳
basis    출처 링크, 캡처 환경(운영/로컬, 해상도), 데이터를 바꾸지 않았다는 확인, 코드로만 확인한 것
section  제목은 명사형, 순서는 결론 → 원인 → 다음 행동
footer   코드 경로, 캡처 일시와 해상도
```

## 3. Hard Rules

1. **캡처 위에 표시를 올리지 않는다.** 박스·번호가 UI를 가린다. 가리킬 것은 캡션에 쓴다.
2. **전/후는 같은 크기로 잘라 나란히 둔다.** 각 캡처 위에 상태 태그("수정 전", "패널에서 수정")를 단다.
3. **확인 범위를 나눠 쓴다.** 화면으로 본 것, 테스트로 본 것, 코드로만 본 것, 미확인. 미확인은 칩과 사유로 표시한다.
4. **같은 대상은 한 이름으로 부르고, 화면 요소는 화면에 표시된 이름으로 부른다.**
5. **요청하지 않은 엣지케이스·방어 규칙을 넣지 않는다.**

## 4. 게시

1. 원본은 사용자가 정한 폴더에 `YYYYMMDD-<티켓>-<주제>.html`로 저장한다. 이미지는 옆 폴더(`_ref/<티켓>/` 등)에 둔다.
2. 아티팩트·정적 호스팅에 올릴 때 `_`로 시작하는 경로를 막는 곳이 있다. 게시본은 `img/<티켓>/`처럼 바꿔 올린다.
3. 게시본을 한 번 열어 섹션 간격, 캡처, 표만 확인한다.

## 5. 문장

- 결과를 먼저 쓰고 내부 동작은 필요할 때 덧붙인다.
- 엠대시를 쓰지 않는다. 문장은 서술어로 끝낸다.
