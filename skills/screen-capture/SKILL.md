# Screen Capture

한 가지만 합니다. 화면을 캡처합니다. 무엇이 문제인지 판단하지 않습니다(`ticket-brief`).

## Hard Rules

1. **운영 데이터를 바꾸지 않는다.** [저장]·[등록]·[발송]은 누르지 않는다. 입력을 바꿔 봤다면 [취소]나 [나가기]로 닫는다.
2. **기준값을 적고 다시 확인한다.** 열기 전에 목록 개수나 수정 날짜를 적고, 닫은 뒤 같은지 본다. 그 결과를 보고서에 적는다.
3. **로딩이 끝난 뒤 찍는다.** 스피너가 보이면 몇 초 뒤 다시 찍는다.
4. **로컬에서 데이터가 필요하면 UI로 만들지 않는다.** 발송이나 예약 작업이 생기는 데이터는 로컬 DB에 직접 넣고, 끝나면 지운다.

## Workflow

1. **준비**: 브라우저 자동화 도구(Aside, Playwright 등)로 로그인된 탭을 연다. 뷰포트는 1440×900을 기본으로 한다.
2. **기준값**: 목록 화면에서 개수·수정 날짜를 기록한다.
3. **열기**: 상세 → 편집 → 패널·다이얼로그 순서로 연다. 진입 경로가 여러 개면 모두 연다.
4. **찍기**: 전체 화면을 찍고, 상태 이름을 파일 이름에 넣는다(`c-editor.png`, `i-panel-edited.png`).
5. **닫기**: 저장하지 않고 닫는다. 새로고침 후 기준값을 다시 확인한다.
6. **자르기**: `sips -c <높이> <너비> --cropOffset <y> <x> in.png --out out.png`. 같은 종류의 캡처는 같은 크기로 자른다.

## 자주 생기는 문제

- 자동화 도구에서 이동 뒤 페이지 컨텍스트가 사라지면 탭을 새로 연다.
- 같은 텍스트가 배경 화면과 패널에 동시에 있으면 텍스트 선택자가 배경 쪽을 누른다. 범위를 좁히거나 좌표로 누른다.
- 화면 밖으로 밀린 요소는 그 요소를 편집하는 상태(스크롤된 상태)로도 찍는다.
