# Implementation Report

한 가지만 합니다. 구현 결과를 보여 줍니다. 작업하면서 내린 판단의 기록(작업 로그)은 쓰지 않습니다.

## Hard Rules

1. **캡처는 구현한 로컬 화면으로 새로 찍는다.** 프로토타입 캡처를 재사용하지 않는다. 확인이 끝나면 저장하지 않고 닫는다.
2. **'언제 나오나' 표는 프로토타입 표와 같은 조건으로 시작하고, 구현에서 달라진 점은 표를 고친다.**
3. **검증은 종류별로 나눈다.** typecheck·lint·테스트·로컬 화면·미확인. 미확인은 사유를 적는다(예: 로컬에 메일 연동이 없음).
4. **'어떻게 고쳤나'는 사용자가 겪는 동작 기준으로 쓴다.** 함수 이름은 변경 파일 표에만.
5. **리뷰에서 반영하지 않은 지적은 반영하지 않았다고 쓴다.**

## Workflow

1. **캡처**: `screen-capture`로 전/후를 같은 크기로 찍는다. 패널처럼 상태가 여러 개면 "열기만 함 / 수정함"을 짝지어 찍는다.
2. **구성**: 요약 3줄 → 근거(PRD·프로토타입 링크, 캡처 환경) → 화면(전/후 짝) + 확정 문구 → 언제 나오나 → 어떻게 고쳤나(번호 단계) → 변경 파일 → 검증 → 남은 확인.
3. **만들기**: `html-report`로 만들고 게시한다.
4. **수정 요청**: 캡처를 다시 찍어야 하는 수정(구분선 추가 등)은 화면을 다시 찍고 같은 주소로 다시 게시한다.
